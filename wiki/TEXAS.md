# 德州扑克

本平台 `game_id`：`holdem`。规则参数固定，Bot 通信使用
[统一信封](#/wiki?slug=protocol)。

## 先说清楚五个单位

- **手**：一次发牌与下注过程。
- **70 手计分场**：连续完成 70 手后，按这 70 手的累计净筹码独立判定一次胜 / 平 / 负，
  分别获得 3 / 1 / 0 分。下一场重新从 0 计算筹码与胜手。
- **复式交锋组**：同一副牌序列交换座位后进行的两场 70 手计分场。两场各自计分，组合没有
  单一胜者；组合计筹码只作为排名的后置破同分数据。
- **对手系列**：同一阶段内与一名对手安排的全部计分场；预赛或决赛可以把数量设为 K。
- **对局记录 / 观赛入口**：平台为运行、直播和回放保存的一条记录。普通记录含一场计分场；
  复式记录正常完成时含两场计分场。因此“记录数”和“计分场数”不能混为一谈。

## 1. 赛局参数

- 双人无限注德州扑克（Heads-Up No-Limit Hold'em）。
- 一场计分场固定 **70 手**，不可通过上传参数或对局配置修改。
- 每手双方起始筹码固定 20000、小盲固定 50、大盲固定 100；每手重新开始。这些参数与 70 手均不可配置。
- 座位 `0` / `1` 轮流担任按钮位与小盲：第 `hand` 手的小盲为 `hand % 2`。
- 每手净输赢累加到当前计分场的 `total_win_chips`；70 手后累计净筹码高者赢，相同为平局。
  复式第二场开始时该值重新归零。

## 2. 行动顺序

- 翻前：按钮位 / 小盲先行动。
- 翻牌、转牌、河牌：非按钮位 / 大盲先行动。
- 有人弃牌时本手立即结束；双方全押后发完公共牌并摊牌。
- 全押的下注总额包含该玩家本街已经投入的盲注和加注。覆盖短码全押的一方只需跟到相同总额，自己可以保留多余筹码；完成跟注后若已没有第二名可行动玩家，平台直接发完公共牌，不再要求单人逐街过牌。

## 3. 动作码

Bot 必须输出完整响应对象，例如 `{"response":0}`。`response` 值的含义：

| 值 | 动作 |
|----|------|
| `-1` | fold |
| `-2` | all-in |
| `0` | call / check；裁判按当前状态判定 |
| `>0` | 本动作额外投入的筹码（raise delta） |

正数不是“加注到的总额”。例如本街已投 50、目标总下注 300，应返回
`{"response":250}`。

最小加注按目标总额校验：面对当前下注额时，新的总下注至少达到裁判要求的最小值；
筹码不足时可选择全押。`response=0` 不携带“跟多少”的数值，平台会按当前水位精确扣除跟注额；
如果正好耗尽剩余筹码，该动作会按 all-in 状态收口。面对已经全押的唯一对手时，覆盖筹码方的合法集只有
fold/call；为兼容仍返回 `-2` 的既有 Bot，平台会把它规范化为精确 call，未匹配的余额不会投入。
除此之外，响应格式正确但游戏内动作不合法时由德州裁判按弃牌处理；
非法 JSON、错误信封或错误 response 类型属于协议技术负，不会伪装成弃牌继续比赛。

## 4. 手牌与牌型

每名玩家两张底牌，桌面最多五张公共牌，从可用七张牌中选择最佳五张。牌型从大到小：

同花顺 > 四条 > 葫芦 > 同花 > 顺子 > 三条 > 两对 > 一对 > 高牌。

支持 A-2-3-4-5 作为最小顺子。完全相同的最佳五张牌平分本手底池。

## 5. 请求 payload

每条 Holdem request 恰好包含 11 个字段：

```json
{"num_players":2,"dealer_id":0,"my_id":0,"my_chips":19950,"my_cards":[48,51],"public_cards":[],"history":[],"hand":0,"max_hand":70,"total_win_chips":[0,0],"total_win_games":[0,0]}
```

| 字段 | 含义 |
|------|------|
| `num_players` | 恒为 2 |
| `dealer_id` | 本手按钮位 / 小盲座位 |
| `my_id` | 本 Bot 座位 |
| `my_chips` | 当前手剩余筹码，盲注和已下注已扣除 |
| `my_cards` | 两张底牌，整数编码 0..51 |
| `public_cards` | 当前公共牌 |
| `history` | 当前手动作历史 |
| `hand` | 当前手序号 0..69 |
| `max_hand` | 恒为 70 |
| `total_win_chips` | 当前 70 手计分场内双方累计净筹码；下一场归零 |
| `total_win_games` | 当前 70 手计分场内双方累计赢手数；下一场归零 |

平台不发送跟注额、对手筹码等派生字段。Bot 从 `history` 与 `my_chips` 重放。

### history

```json
{"round":0,"player_id":0,"action":250,"action_type":"raise"}
```

- `round`：0 preflop、1 flop、2 turn、3 river。
- `player_id`：行动座位。
- `action`：与 response 动作码相同；raise 时为额外投入筹码。
- `action_type`：`fold` / `allin` / `call` / `check` / `raise`。

## 6. 卡牌编码

牌编码范围 0..51：

```text
card = (rank - 2) * 4 + suit
rank = card // 4 + 2
suit = card % 4
```

花色：`0` 红心、`1` 方块、`2` 黑桃、`3` 梅花。例如 `48` 是 A♥，`50` 是 A♠。

## 7. 锦标赛流程

德州赛事按“草稿 → 开放报名 → 发布排期 → 开赛 → 阶段休息（模板包含时）→ 已结束”推进。
每场计分场仍严格使用本页固定的 70 手规则，胜 / 平 / 负立即按 **3 / 1 / 0** 进入阶段积分。
赛事积分与赛果不会进入平台 Glicko Rating。

新建德州赛事默认推荐 **复式单循环（公平优先，≤12 人）**：每对 Bot 使用同一副牌序列交换座位
各赛一场，减少发牌与座位差异。创建普通单循环赛事时，“每对选手计分场数”可设为 1–10；
创建复式赛事时填写的是“每对选手复式交锋组数”，每组正常包含两场独立计分的 70 手比赛。
例如选择 3 组会产生 3 个观赛入口、计划 6 场计分。技术终局只按裁判实际产生的计分场结算，
不会补造第二场。偶数组严格平分物理座位，奇数组每对只差 1 次，额外座位按整个排期确定性轮换。

**预赛与决赛公平设置**：`德州：预赛` 的每轮对手系列默认打 2 场独立计分场，并在自动轮数上增加
2 个瑞士轮；可在草稿或报名中调整为每对 1 / 2 / 4 场、附加 0–4 轮，但不会超过无重复对手的
覆盖上限。`德州：决赛` 的全员循环默认每对 2 场，Top 8 决胜默认每对 4 场，各阶段可按页面
给出的安全档位调整。设置保存后页面会重算对手系列、计分场、有效瑞士轮与预计耗时；排期一经
发布即冻结，进行中和历史赛事不会被新默认值改写。旧的草稿/报名赛事若还没有这些字段，会在
首次保存或发布时补入当前模板默认值。

上述预赛/决赛使用独立发牌。K 场中的每一场都独立判胜并立即获得 **3 / 1 / 0** 分，不再先记
小分、等整组结束后只结算一次。K 场必须全部终结且系列坐标完整，平台才会生成下一瑞士轮、
推进阶段或固化正式榜；已完成场的积分会即时显示。技术判负只产生一条真实计分记录，平台故障
中止不计分。

瑞士轮轮空不会虚构对手或胜负记录：K=1 时补偿 3 分；K=2 或 K=4 时，每两场按“一胜一平”
等值补偿，合计为 `2K` 分。正式榜单列轮空次数，轮空不增加胜 / 平 / 负、计分场数、对手数或
筹码差；对手强度破同分使用 K 条虚拟记录，每条虚拟对手分取“该选手最终积分”和“平局分 ×
该阶段个人计划计分场数”中的较小值，避免轮空选手因没有真实对手而被额外惩罚；虚拟记录不进入
直接交手得分率。

- **瑞士 → 单败 / 预赛瑞士**：每轮中同一对手的系列全部结束后才生成下一轮，优先安排同分且
  未交手的对手；基础轮数按 `ceil(log2(参赛人数))` 计算，预赛模板可再增加 0–4 轮并受无重复
  对手覆盖上限约束。
- **单循环 / 复式单循环**：普通模板配置每对计分场数；复式模板配置每对复式交锋组数。每组用
  同一副牌序列交换座位进行两场独立计分场，组合计筹码只用于破同分。
- **循环 → Top 8 双循环决赛**：全员循环结束后前 8 名进入休息期；两阶段分别使用各自冻结的每对
  交锋场数，Top 8 名次覆盖全员循环的前 8 名，未晋级选手保留上一阶段顺序。

排期发布后冻结该轮双方 Bot 版本；休息期只有模板明确允许时才能换 Bot。完赛正式榜先按积分，
同一阶段、同一晋级组内同分时，再依次使用 Buchholz Cut1、Sonneborn-Berger、直接交手得分率、
累计标准化筹码差、技术负次数和报名序。新计分版本的 Cut1 删除最低的一条对手分记录；重复
交手逐场进入对手强度，直接交手按 `(胜 + 0.5 × 平) / 场数` 计算。累计筹码只在上述更高优先级
仍相同时生效，绝不生成复式交锋组的整体胜者。完整平台生命周期与排队规则见
[平台功能指南](#/wiki?slug=guide)。

这套口径参考 FIDE 的
[破同分规则](https://handbook.fide.com/chapter/TieBreakRegulations032026)与
[Double-Swiss 规则](https://handbook.fide.com/chapter/DoubleSwissSystem202602)：重复交手按独立记录参与
对手强度，每组两场分别计分。轮空的 `2K` 补偿与虚拟对手分是本平台面向 3 / 1 / 0 计分和 K 场
系列的明确扩展，不把未进行的比赛伪装成实际胜 / 平 / 负。

**四人示例**：每对 1 组复式时，全阶段共有 6 组复式交锋、12 场计分；每人面对 3 位对手，
参加 3 组复式交锋并完成 6 场计分，所以个人胜 / 平 / 负合计为 6，而不是 3。阶段进度、个人
参赛数和计分场战绩会分别标出单位。

## 8. 快速开始

最简单的合法策略始终返回 `{"response":0}`，即在可过牌时过牌、需要跟注时跟注。
[Bot 开发指南](#/wiki?slug=bot-dev)提供可直接复制的完整 C / Python 程序，以及在 Windows、
Linux、macOS 上构建 Linux x86_64 ELF 的命令。上传时选择的运行模式必须与程序处理信封的
方式一致。
