# 平台功能指南

本页只介绍访客、Bot 玩家与赛事组织者在网页上能看到和操作的功能。游戏规则见
[德州扑克](#/wiki?slug=texas)、[五子棋](#/wiki?slug=gomoku)和
[点格棋](#/wiki?slug=pencil)；Bot 输入输出格式见[通信协议](#/wiki?slug=protocol)。

## 1. 对局

### 发起挑战

登录后进入“挑战”页：

1. 选择游戏；
2. 座位 1 选择自己的 Bot；
3. 座位 2 可选择其他公开 Bot、自己的 Bot进行自博弈，或选择“我亲自上场”；
4. 确认后进入对局页，等待排队、运行与结算。

两个座位都选择 Bot 的普通挑战会更新双方该游戏的 Glicko-2 评分。锦标赛对局只计赛事
成绩；人类亲自上场不计 Bot 天梯评分。系统也会在空闲时安排天梯对局，以维持排行榜活跃度。

### 人类亲自上场

- 人类固定坐在座位 2（内部座位 1；棋类为白方/后手），座位 1 必须选择 Bot；
- 德州扑克使用弃牌、跟注/过牌、加注和全押按钮；
- 五子棋与点格棋直接点击棋盘；
- 刷新或短暂断线后可恢复当前局面与待操作回合；
- 普通人类回合最多等待 120 秒；点格棋还为双方分别计算 900 秒累计棋钟；
- 同一回合只接受一次操作，连续点击不会重复提交。

Bot 协议错误、超时或崩溃会在对局结果中显示明确原因。平台沙箱自身故障会把对局标为
中止，不会误算为某个 Bot 的技术负。

### 观赛与回放

对局页会根据游戏展示对应界面：

- 德州扑克：底牌、公共牌、行动、筹码与每手结算；
- 五子棋：棋盘、最后一手与胜负；
- 点格棋：边、已占方格、比分、双方累计棋钟与超时标记。

正在运行的对局会实时更新；已结束对局自动切换为可逐步浏览的回放。页面会显示双方名称、
座位、胜者、对局类别和终局说明。状态“已完成”表示裁判已经结算；连五、平局、过半和按比分
判定等正常原因使用中性文案，非法动作、协议错误、超时、崩溃和平台故障才使用警示文案。
未知的历史完成原因会归纳为“已完成”，不会把内部英文码直接展示给用户。回放滑条按“事件”计数，顶部的总手数或总步数以最终结果为准，
不会随回放游标变化。若 Bot 在首个决策就因协议问题判负，页面会直接显示故障座位、决策序号、
错误代码与说明，不展示没有实际意义的逐手播放控件。展示座位从 1 开始，规则与协议中的座位编号
从 0 开始。

真人德州扑克进行中，公开观赛不会展示任一方底牌或真人决策请求；登录本人只在对战页看到
自己座位的底牌。对局结束后，完整发牌记录才进入公开回放。

观赛和人类对局的事件列表使用中文说明：点格棋的非法连边、棋钟用时和 Bot 技术故障会显示
对应座位、决策或用时信息，不会把内部事件码或运行路径直接展示给玩家。

### 常见结果

| 情况 | 页面结果 |
|------|----------|
| 正常完成 | 显示胜者或平局，并保留完整回放 |
| Bot 响应不符合通信协议 | 协议错误，Bot 技术判负 |
| Bot 决策超时 | 超时，Bot 技术判负 |
| LongRunning 握手缺失或内容错误 | 协议错误，Bot 技术判负 |
| 响应格式正确但动作违反游戏规则 | 由该游戏裁判判罚 |
| Bot 运行中崩溃 | 崩溃方判负，并显示异常原因 |
| 平台沙箱故障 | 对局中止，不计 Bot 技术负 |

## 2. 裁判

“裁判”规则说明页对所有访客开放，可查看三款游戏的规则说明和判定依据。它用于说明平台如何
判断合法动作、推进局面和计算胜负；玩家上传的 Bot 二进制仍然私有。

规则摘要：

- **德州扑克**：固定 70 手；每手起始筹码 20000，小盲 50、大盲 100；按 70 手累计净筹码判胜；
- **五子棋**：固定 15×15，黑方先手，无禁手，连续不少于五子即胜；
- **点格棋**：固定 N=6，共 25 格；成格后连走；双方各有 900 秒累计棋钟。

这些规则不能在挑战或赛事中临时改写。

## 3. 排行榜、段位与等级

排行榜可按游戏筛选。每款游戏单独维护 Glicko-2 评分、排名变化和段位：

| 段位 | 最低评分 |
|------|----------|
| 大师 | 2200 |
| 专家 | 2050 |
| 高手 | 1900 |
| 熟练 | 1750 |
| 进阶 | 1600 |
| 新手 | 0 |

Bot 详情页会显示当前评分、不确定度、胜率、胜负平、最近对局、对手战绩与评分曲线。
新 Bot 的前 10 场计分对局属于定级期；排行榜和 Bot 详情会显示“已完成/需要”的定级进度，
打满后才展示正式段位。排行榜先列出已完成定级的 Bot，再列出仍在定级的 Bot，避免高不确定度
的初始评分被误看成正式名次；定级 Bot 的名次栏显示“—”。对手交手场数严格等于胜、负、平之和。

用户等级与 Bot 段位是两套系统。用户通过参与和赢得普通对局、报名赛事、评论及被关注获得
经验；个人主页会显示等级与经验进度。

## 4. 锦标赛

### 角色与报名

- 访客可查看已公开赛事、赛程和成绩；
- 登录玩家可在开放报名期间派遣与赛事游戏一致的、当前可运行的自己的 Bot；
- 已报名玩家可在允许的阶段更换派遣；
- 组织者可创建赛事、开放报名、发布当前排期、开始比赛、推进阶段、导出名单与成绩；
- 管理员用于审计和故障处理，不替代赛事正常流程。

需要实名的赛事会在报名时检查姓名、手机号、学校和学号。实名信息只对该赛事组织者与管理员
可见，不会出现在公开报名列表中。

### 生命周期

赛事依次经历：

1. **草稿**：组织者编辑信息，公众不可见；
2. **开放报名**：玩家报名或更换 Bot；
3. **排期已发布**：报名截止，当前可确定的轮次已经生成，等待开赛；
4. **比赛中**：按排期派发对局；
5. **阶段休息**（如模板包含）：显示阶段成绩，并按规则允许换 Bot；
6. **已结束**：正式名次与成绩固化。

组织者也可在开赛前取消赛事。**“已结束”和“已取消”都是终态，二者不能互相推进，也不能
回到更早阶段。** 管理端只显示当前阶段真正可执行的操作，不会在已结束赛事上出现“取消”。

“强制结束赛事”只用于恢复性收尾：所有关联对局已经完成或中止，但自动推进没有收敛时，
平台会再次核验后固化名次；仍有待开或运行中对局时会拒绝。

### 时间顺序

赛事时间必须满足：

```text
开放报名时间 ≤ 报名截止时间 ≤ 比赛开始时间
```

三个时刻可以相同。创建和编辑都会整体校验，非法组合不会部分保存。若历史赛事存在倒挂，
管理端会明确标红，管理员需在“修正时间”中改为合法顺序；平台不会把错误时间当作另一套规则。

比赛开始时间可以留空。留空时，发布只会生成当前排期，赛事会停在“排期已发布”，直到组织者
点击“开始比赛”；报名截止不会自动触发开赛。填写开始时间后，平台才会在该时间到达后自动派发。

### 赛制与排期

平台提供单循环、双循环、分组循环、瑞士轮与单败淘汰等模板。小规模赛事适合循环赛；人数较多
时优先使用瑞士轮加淘汰赛，避免场次数平方增长。

排期页按阶段和轮次显示双方、计划时间、对局状态与回放入口。淘汰赛使用树状对阵；循环、
分组和瑞士轮按轮次折叠。瑞士轮与淘汰赛后续轮依赖当前结果，因此“排期已发布”只承诺当前
已经确定的批次，不会提前伪造整届赛事的全部对阵。

平台只按可用并发槽启动对局；尚未取得槽位的对阵保持“待开始”，不会提前显示为“进行中”。
一场对局结束后，其对阵状态会立即更新为“已完成”，再补入下一场待开始对局。

每个已发布对阵都会冻结双方当时激活的 Bot 版本。随后上传或回滚只影响未来尚未发布的轮次，
不会改变已发布对局实际运行的程序。

## 5. Bot 与版本管理

### 上传

“我的 Bot”页只接受 **Linux x86_64 ELF64（小端）**，最大 50MB。Windows `.exe`、macOS
Mach-O、ARM64 ELF 和原始 `.py` 都会被拒绝。Linux、Windows 与 macOS 的 C/Python 构建
方法见 [Bot 开发指南](#/wiki?slug=bot-dev)。

上传时选择游戏和运行模式：

- **Traditional（默认）**：每个决策点启动新进程，发送完整历史；
- **LongRunning**：进程整场保留，首响应后必须输出精确握手，之后接收增量请求。

两种模式使用同一套请求 payload 和 `response` 信封；LongRunning 握手失败不会回退。

### 版本

每个 Bot 可保留多个版本，并在可运行版本之间切换。上传新版本会先进行与正式首回合相同的
协议预检，通过后才成为当前版本；失败不会改变原版本。

页面标记为“不可运行”的版本不会出现在公开对手、搜索或赛事报名候选中，也不能启用或
回滚激活。请上传 Linux x86_64 ELF 版本替代。

## 6. 用户主页、搜索与社交

用户主页显示头像、显示名、简介、角色、等级、总战绩和公开 Bot。可以从排行榜、Bot 详情和
对局页点击用户名进入，也可以在全局搜索中按用户、Bot 或对局查找。

登录用户可以：

- 关注或取消关注其他用户；
- 收藏或取消收藏公开 Bot；
- 在 Bot 与对局详情发表评论；
- 为 Bot 或对局点赞；
- 在通知页查看被关注、评论、普通对局完成和赛事阶段变化。

评论作者可删除自己的评论，管理员可处理违规内容。通知邮件默认关闭，可在个人设置中按类别开启；
邮件发送失败不会影响站内通知。已删除或不存在的用户、Bot、对局和评论不能继续被关注、收藏、
评论或点赞；删除对象时其关联互动会同步清理。自己在自己的 Bot 或对局下评论不会给自己发送通知。

## 7. 个人设置

个人设置包含：

- 头像、显示名和简介；
- 修改密码；修改后所有已有会话都会失效，需要重新登录；
- 通知与邮件偏好；
- 收藏的 Bot 列表；
- 实名资料（参加要求实名的赛事时使用）。

完整 Bot 协议与跨平台构建说明见 [通信协议](#/wiki?slug=protocol)和
[Bot 开发指南](#/wiki?slug=bot-dev)。
