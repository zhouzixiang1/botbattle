# 浏览器验收矩阵

本文给出发布前必须执行的四角色浏览器验收范围。它是验收清单，不以“页面能打开”代替业务操作，也不把 API 单测结果冒充浏览器证据。实际执行结果只记录在 [TESTING.md](./TESTING.md)。

## 1. 统一观察标准

每条适用用例都要同时检查：

- 视口：Desktop `1440×900`、Laptop `1280×720`、Mobile `390×844`；移动端还要展开菜单并验证返回页面。
- 滚动：页面顶部、中部、底部均实际滚动；长列表、Dialog、Tab 和独立滚动区不能截断最后一项。
- 截图复核：矩阵中的每个页面都要在首屏、滚动中段和页尾保存截图，并以图片识别逐张判断设计 token、字号层级、组件尺度、留白、信息密度、对齐、换行、截断、粘性区域和内外滚动是否协调；不能用 DOM 断言或“能打开”替代视觉证据。Desktop 与 Mobile 全覆盖，Laptop 对数据表格、管理端、对局和赛事等高风险页面全覆盖。
- 跨页一致性：同级页面的 PageHeader、工具栏、摘要、筛选、数据区、空/错/加载态和危险操作必须使用同一套视觉语言；Admin 不得形成另一套间距、颜色、字号或控件体系。装饰性内容不能挤占主任务，首屏必须优先展示可操作信息。
- 长文本：中文长句、至少 128 字符的连续英文/数字、emoji、长用户名/Bot 名/赛事说明不能撑破卡片、表格或视口；允许局部表格横向滚动，但根元素横向溢出不得超过 1 px。
- Console：`pageerror`、未列入白名单的 `console.error` 和 `console.warning` 均失败。
- Network：同源普通 HTTP 的 `requestfailed`、未列入白名单的 4xx/5xx、请求长期未收敛均失败；SSE/WS 由专门用例验证连接、消息和关闭语义。
- 导航：直接深链、刷新、浏览器返回/前进、站内链接和未知路由回首页都要验证；不能只断言通用标题。
- 写操作：双击或快速重复点击仍只能产生一次请求；成功后检查返回实体和最终 UI，失败后检查可恢复错误态。

全局执行队列重构还必须在目标 HEAD 上确认下列真浏览器证据，未执行前均为“待验证”：

- Challenge 捕获 POST 202 响应，断言排队阶段没有 Match/跳转；轮询采用同一 `public_id`，刷新和短暂
  离线后恢复；claim 返回 `match_id` 后只跳转一次。
- queued 取消、active 危险确认/安全收敛、interrupted 重试三条分支分别检查 UI、Network、最终状态，
  并确认 active 清理前全局容量不提前回升、旧 attempt 不被改写。
- 混合 manual/human/contest/auto 队列展示须核对 source、前台内 aging 后顺序、6 个 match slots 与 12 个 sandbox units；
  每个 job 仍占 1 match slot，人机只计 1 sandbox unit，资源向量可把实际并发压到 1–6，赛事份额 1 不得显示或计算成额外物理槽。同一非 human Bot 的第二个 active 请求保持排队；contest 轮转不跨 manual/human 边界。
  auto 须无前台数字顺位，不计入用户请求的 `ahead_jobs`/ETA，并显示最多 1 场/1 候选与让路原因。公开投影不得出现 DB id、版本 id、路径、checksum、token 或 match_config。
- 管理端切 auto 只影响闲时生产能力，开启不等于立即运行；顶层 `auto_scheduler` 的 disabled/foreground_busy/contest_guard/cooldown/ready/yielding/running 须有可见文字与 `aria-live`，稳定机器原因码不直出。paused 恢复按钮须经过确认，并在模拟 Docker 清理不确定时仍显示
  paused/重试时间。Console、普通 HTTP Network、轮询收敛与后端日志同时检查。

自动化的 DOM/像素尺寸断言不能替代逐图视觉判断：发布候选必须对页面矩阵的首屏/中段/页尾截图逐张做图片识别复核，并在 Chromium/Firefox/WebKit 的差异页面抽查牌桌比例、长代码滚动、移动端 Dialog 和日期控件。发现大面积无效留白、组件尺寸失衡、跨页风格漂移、不自然换行、文字越界或滚动后结构失衡时，必须回到统一组件/token 修复后重拍；任何未执行项写“待验证”，不能从相邻用例推定通过。
