# 浏览器验收矩阵

本文给出发布前必须执行的四角色浏览器验收范围。它是验收清单，不以“页面能打开”代替业务操作，也不把 API 单测结果冒充浏览器证据。实际执行结果只记录在 [TESTING.md](./TESTING.md)。

## 1. 统一观察标准

每条适用用例都要同时检查：

- 视口：Desktop `1440×900`、Laptop `1280×720`、Mobile `390×844`；移动端还要展开菜单并验证返回页面。
- 滚动：页面顶部、中部、底部均实际滚动；长列表、Dialog、Tab 和独立滚动区不能截断最后一项。
- 长文本：中文长句、至少 128 字符的连续英文/数字、emoji、长用户名/Bot 名/赛事说明不能撑破卡片、表格或视口；允许局部表格横向滚动，但根元素横向溢出不得超过 1 px。
- Console：`pageerror`、未列入白名单的 `console.error` 和 `console.warning` 均失败。
- Network：同源普通 HTTP 的 `requestfailed`、未列入白名单的 4xx/5xx、请求长期未收敛均失败；SSE/WS 由专门用例验证连接、消息和关闭语义。
- 导航：直接深链、刷新、浏览器返回/前进、站内链接和未知路由回首页都要验证；不能只断言通用标题。
- 写操作：双击或快速重复点击仍只能产生一次请求；成功后检查返回实体和最终 UI，失败后检查可恢复错误态。

## 2. 页面与权限矩阵

表中“读”表示真实加载并检查关键内容；“操作”表示还要完成该角色的主业务动作；“门禁”表示验证登录引导或 403/隐藏入口；“—”表示该角色没有合理业务路径，不能为了凑矩阵绕过权限。

| 页面/路由 | 未登录 | 普通用户 | 组织者 | 管理员 | 主要验收点 |
|---|---|---|---|---|---|
| Shell、首页 `/` | 读 | 读 | 读 | 读 | 侧栏/移动菜单、主题、全局搜索、无重复指标、长公告折行 |
| 挑战 `/challenge` | 门禁 | 操作 | 操作 | 操作 | Bot-v-Bot、自博弈、指定版本、人类后手、重复提交 |
| 排行榜 `/leaderboard` | 读 | 读 | 读 | 读 | 游戏筛选、分页、段位、空状态 |
| 对局历史 `/history` | 读 | 读 | 读 | 读 | 状态/游戏/技术故障筛选、错误恢复、分页 |
| 对局 `/match/:id` | 读 | 读 | 读 | 读 | live 从首事件推进、终态切回放、长动作列表、异常原因、SSE 收敛 |
| Bot `/bot/:id` | 读 | 操作 | 操作 | 操作 | 版本/战绩、关注、收藏、评论、长说明、不可运行标识 |

## 3. 角色操作矩阵

| 编号 | 角色 | 必做操作 | 最小证据 |
|---|---|---|---|
| G-01 | 未登录 | 六个主导航、所有公开深链、刷新/前进/后退、搜索、404、登录失败、注册/验证/重置边界 | DOM + URL + Console/Network + 三视口/滚动 |
| U-01 | 普通用户 | UI 登录/退出，编辑个人资料和通知偏好 | POST/PUT 只发生一次，刷新后值一致 |
| U-02 | 普通用户 | 上传真实 Linux x86_64 ELF；上传真实 Windows x64 PE 并被拒绝 | 成功 Bot 可见；PE 为精确 400 且 DB 中无新 Bot |
| U-03 | 普通用户 | 编辑 Bot、上传版本、回滚、激活、删除无引用的临时 Bot | 版本号和 active 状态一致；失败不改旧版本 |
| U-04 | 普通用户 | Bot-v-Bot、自博弈、人类对局 | 单请求、进入 viewer/play、SSE/WS 到权威终态 |
| U-05 | 普通用户 | 赛事报名、换 Bot、退赛；关注/收藏/评论/点赞 | 页面计数、刷新结果和 API 返回一致 |
| O-01 | 组织者 | 三游戏切换与代码模板，标题/说明/实名/时间边界建赛 | game/template 不串线；留空时间仍为 `NULL` |
| O-02 | 组织者 | `draft→open→published→running→(rest)→finished` | 报名截止只发布排期；`starts_at=NULL` 不自动开赛 |
| O-03 | 组织者 | 名单/实名门槛、CSV 导出、阶段 Tab、对阵/进度、手动恢复动作 | 权限、脱敏、下载内容和阶段文案一致 |
| A-01 | 管理员 | 总览、用户、Bot、对局、赛事、日志、邮件七 Tab | 每 Tab 查询参数/返回行数/UI 一致，三视口无根溢出 |
| A-02 | 管理员 | 用户角色/会话/重置，Bot 处置，对局中止，赛事名册/生命周期/删除 | 危险动作有统一确认；活跃/终态保护返回明确错误 |
| A-03 | 管理员 | 赛事时间：空值不预置；自动开赛切为手动时发送 `starts_at:null`；非法顺序零部分写 | PATCH 请求体、重新加载值、audit 日志三方一致 |
| A-04 | 管理员 | 日志文件/级别/关键字/traceback；邮件模板/发件箱 | 无绝对路径泄漏，长日志/邮件正文可滚动不溢出 |
| A-05 | 管理员 | 查询运行参数与赛制模板来源 | 只读 `source=code, mutable=false`，写接口不存在 |

## 4. 自动化落点

| Spec | 已自动化的矩阵子集 |
|---|---|
| `public-audit.spec.ts` | G-01 的公开深链、导航历史、404、登录失败、Network 故障恢复 |
| `qa-regression.spec.ts` | 三视口公开页与受保护页访客门禁、U-02～U-04 的核心链路、实时通信、协议/二进制/版本/异常终态与权限回归 |
| `contest-workflow.spec.ts` | U-05 的报名、O-01/O-02 的建赛与真实多浏览器主生命周期、终态清理保护 |
| `admin-audit.spec.ts` | A-01、A-03、A-05，以及 A-02/A-04 的只读和部分写操作；含赛事时间 `NULL`、非法排期、不同生命周期内容、长文本与滚动 |

自动化尚不能替代人工视觉判断：发布候选还要在 Safari/Chromium 各抽查一次牌桌比例、长代码滚动、移动端 Dialog 和日期控件。任何未执行项必须写“待验证”，不能从相邻用例推定通过。

## 5. 当前待补浏览器证据

33 条现行 Playwright 全部通过不等于上表每个动作都已有自动化。仍需按优先级补齐：

- **P1**：设置页资料/头像/实名/密码与通知偏好的真实写入和回滚；通知逐条/全部已读；关注、收藏、评论、点赞的 UI 往返；赛事换 Bot/退赛/实名门槛/CSV 导出；管理员用户/Bot/名册的危险写操作。这些路径已有后端测试或局部 UI 覆盖，但没有完整浏览器事务证据。
- **P1**：邮箱验证和密码重置的真实发信链路需要隔离 SMTP 收件箱，当前浏览器套件只覆盖表单与后端契约，不能在生产 SMTP 上测试。
- **P1**：德州直播从首事件开始、牌桌比例和终局跳转的视觉修复由独立 viewer worktree 负责；本分支不越界改动，合并后需在同一最终提交重跑。
- **P2**：Wiki 每个 slug、裁判每个源码文件的浏览器内切换与长代码滚动；Safari 的日期控件/移动端 Dialog；长公告、用户简介、Bot 说明、日志、邮件正文的极限连续文本逐页抽查。

这些条目是“待验证”，不是已确认产品故障；一旦执行，结果与证据应回填 [TESTING.md](./TESTING.md)，而不是删除矩阵项目。
