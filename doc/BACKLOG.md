## 优先级与状态定义

- P0：用户已明确要求且方案就绪。P1：影响线上观感、安全或一致性。P2：改进项。P3：打磨项。
- 状态：待开工 / 进行中 / 已合并（附 PR 号）/ 已关闭（不做，附原因）。
- 标「需授权」的条目涉及生产数据库写入、凭据操作或他人产物处置，必须先获得用户对精确范围的授权。

## A. 功能与体验

### A1 单文件源码上传 + 代码编辑器 UI（P0）

- 现状：源码上传只收 zip。后端非 ELF 一律校验 zip 魔数（`bzplat/backend/bots/manager.py:100`）；前端文件选择器 `accept=".zip"` 且文案明说裸 `.py` 不支持（`MyBots.tsx:536`、`BotVersionManager.tsx:377`）；全库无粘贴代码 UI。上传端点为 `POST /api/bots` 与 `POST /api/bots/{id}/versions`（`api_routes.py:1416` 起），`source_build.py` 已有各语言默认入口约定（`DEFAULT_ENTRIES`：c→main.c、cpp→main.cpp、go→main.go、python→`__main__.py`）。
- 影响：用户要本地打 zip 才能传源码，与「在线平台」体验不符；用户已明确要求改为单文件 + 编辑器。
- 方案：后端在上传 admission 内把单源文件合成为标准 zip（按 `DEFAULT_ENTRIES` 命名，语言由扩展名白名单映射），之后完全复用既有 zip 校验、构建、版本冻结链，不新增第二套解析路径；前端 MyBots 与 BotVersionManager 两处表单增加「粘贴代码」输入方式（语言联动入口名、有界文本域、大小预检），与文件上传二选一。
- 验证：单测覆盖合成 zip 进既有管线、扩展名白名单、超限拒绝；e2e 上传链路；上传预检回归。
- 前置：无。

### A2 云存储面板双列化（P1）

- 现状：`UserStoragePanel.tsx`（247 行）文件清单是单列 `divide-y` 行式列表（L210 起）；`/storage` 页面仅 31 行薄壳。#226 存储改造已上线并稳定。
- 影响：文件多时纵向过长，空间浪费。
- 方案：清单改响应式网格（sm 两列 / xl 三列卡片，参照 `Search.tsx` BotResults 网格），行内上传/删除行为不变。只动 `UserStoragePanel.tsx`，后端零改动。
- 验证：`npm run build` + 目标 Playwright + 1440×900 与 390×844 双视口。
- 前置：无。

### A3 搜索页三结果并列（P1）

- 现状：`/api/search` 一次只返回一类（users/bots/matches，`api_routes.py:1236` 起）；`GlobalSearch`（Cmd+K）已示范对同一关键词并行发 3 个请求分三组渲染；但 `/search` 页是单 type 视图，Tab 切换一次只看一类（`Search.tsx:97` 起）。搜索类不含赛事（赛事走 `/api/contests`）。
- 影响：结果页需要手动切 Tab 才能看全三类。
- 方案：纯前端——`Search.tsx` 一次并行拉三类，纵向三个 section 复用现有三个结果组件；URL `type` 参数转为定位锚点。后端零改动。
- 验证：`npm run build` + Playwright（含某类为空的空态）。
- 前置：无。

### B4 挑战页移动端分步向导（P2）

- 现状：`Challenge.tsx` 1187 行单长表单；桌面 xl 双列一屏可容纳，390px 下全部单列纵向堆叠，长度可观。
- 影响：移动端配置一场对局要长距离滚动，易漏项。
- 方案：移动端分步（游戏与时限 → 两个座位 → 确认提交），桌面保持现有一屏布局；提交幂等键（`request_id`）与 sessionStorage 恢复语义原样保留；复用 `OpponentPickerModal`、`ExecutionRequestCard`、时限选择组件。
- 验证：三浏览器矩阵 + 幂等恢复用例 + 双视口。
- 前置：无。

### B5 密度二轮：排行榜/历史页（P2）

## 明确不做与边界

登记为「边界」防止计划膨胀；推翻任何一条都先改本文件再动工。

- **多 worker 部署**：内存限流与 SSE/WS 配额只承诺单进程（DESIGN/RUNTIME/SECURITY 一致），扩 worker 前必须先建共享后端，未立项。
- **admin 日志历史轮转分页**：接口只读当前轮转末 8000 行，是登记过的边界，暂不扩展。
- **Bot 名称墓碑复用**：`UNIQUE(owner_id,name)` 覆盖墓碑行，暂不开放复用。
- **对局数据导出（matchpacks）**：已下线的整包导出能力不重新承诺；现行按游戏的单场棋谱导出（`/api/matches/{id}/record`）不受影响。
- **git 历史改写**（E12 第二步）：不与任何其他工作捆绑，必须独立授权立项。
